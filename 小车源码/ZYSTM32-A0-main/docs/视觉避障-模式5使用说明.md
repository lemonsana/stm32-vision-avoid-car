# 模式5：K210视觉触发、定时绕行、灰度回线

原来的模式1（超声波融合）、2（避障）、3（循迹）、4（自检）全部保留。新增模式5，并将上电默认模式改为模式5；不改原循迹PID、电机、灰度、遥控驱动或Flash参数格式。原工程的遥控任务IR_IN本就没有注册，本次保持原样，没有额外启用遥控任务与自动驾驶争用电机。

## 使用

1. 打开 `USER/Template.uvprojx` 编译烧录小车；工程已加入两个视觉C文件与头文件搜索路径。本次只改了 `SYSTEM/vision/vision_avoid.h` 和 `vision_avoid.c`，**必须用 Keil 重新编译生成 hex 再烧录**；仓库里现存的 `OBJ/vision.hex` 是加入距离门限之前的旧固件（那台机器上没有 ARMCC，无法在此重新生成）。
2. 将 `K210配套/main.py` 部署为K210启动脚本。它基于本次补充的、已打通通信的ybserial代码，不改串口引脚配置、模型路径或模型参数。`K210配套/通信原版.py` 保存了补充代码原文。顶层原 `k210/main.py` 和 `stm32代码` 未改。
3. 接线沿用通信实验：K210 TX → 小车PA3（USART2 RX），两板GND共地，115200/8N1。小车PA2配置为USART2 TX，目前不主动发送。USART1 PA9/PA10继续用于USB调试与原调参指令。确认实际板子PA3接点；不要将USB调试的TX信号与K210 TX同时接入PA3。
4. 小车上电默认进入模式5并立即运行原灰度循迹；K210未就绪或在正常压线阶段暂时断线时，继续灰度循迹但不触发视觉避障。收到K210数据且目标达到条件后才离线。若已经开始绕行后通信中断，则停车保护。也可以用小车USB串口发送 `5` 加换行重新启动模式5。
5. 发送 `3` 加换行可回原纯循迹模式，其余模式照旧。模式5故障停车后不会自行恢复，排查后重发 `5` 重启该模式。

原K210发送器无目标时心跳为1秒，丢失目标后延迟500ms报告；不能直接配本版500ms断链阈值使用。配套版改为有无目标均每50ms发送一次当前结果，不保留丢失目标。ybserial数据格式原样保留。若一定使用通信原版，应将断链阈值调到大于1秒并留余量，但会延长故障检测，且原版最高置信度选框不等于最近障碍，不推荐用于本功能。

## 动作和调参

只对前方通道内的类别0目标处理，并且要过 **距离门限**：估算距离进入 `VA_TRIGGER_CM`（默认 10cm）才算一次命中，最近 3 个新检测帧里命中 2 帧才触发。多目标时选面积最大的前方目标。K210用四个标量卡尔曼滤波器平滑框中心与宽高，再发送给STM32。默认图像320×240，通道横向范围60～260。YOLO解码基础阈值0.3，用来决定是否产生检测框；12px 以下的小框直接丢弃。

主参数集中于 `SYSTEM/vision/vision_avoid.h`，改后重新编译烧录，原SET/SAVE只管理原循迹参数，不管理本次宏参数。默认值只是低速试车起点，不是已标定参数。

| 参数 | 初值 | 含义 |
| --- | --- | --- |
| VA_ROW_AT_10CM / VA_ROW_AT_20CM | 200 / 104 | 两点标定的框底边行号（10cm、20cm）；默认按 相机高10cm、俯角15°、f≈260px 估算，**装车后必须实测一次** |
| VA_TRIGGER_CM | 10 | 估算距离 ≤ 它才开始绕行；改 0 = 关闭距离门限，退回"看到框就绕"的旧行为 |
| VA_PREDICT_MS | 60 | 时延补偿：按最近两帧底边行号的变化率把判定提前这么多毫秒；0 = 只用原始测量值 |
| VA_CONFIRM_HITS / VA_CONFIRM_WINDOW | 2 / 3 | 最近3个新检测帧里"命中"2帧即触发（命中=类别对+在通道内+距离已达标）；想更快就把 HITS 改 1（单帧触发，误检也会直接绕行） |
| VA_LEFT | 1 | 固定左绕；0右绕，选场地允许的一侧 |
| VA_SPEED / VA_TURN_SPEED | 60 / 60 | 绕行前进与原地转向PWM，非实际速度 |
| VA_TURN_OUT_MS | 300 | 原地向外转向 |
| VA_SHIFT_MS | 600 | 斜向前进，侧移离线 |
| VA_STRAIGHTEN_MS | 300 | 原地反向转，大致平行原轨道 |
| VA_PASS_MS | 1000 | 沿障碍侧面前进，车尾应完全超过障碍 |
| VA_TURN_IN_MS | 300 | 原地朝轨道方向转向 |
| VA_SEEK_SPEED / VA_SEEK_TIMEOUT_MS | 45 / 3000 | 斜向前进找线速度与最大时间 |

| VA_COOLDOWN_MS | 500 | 回线后循迹、不重复触发的时长 |
| VA_LINK_TIMEOUT_MS | 1500 | 有效通信帧过期停车，兼容原K210无目标时每1秒心跳 |

## 为什么"避障开始得太早、回线也太早"

旧版触发条件只有"类别对 + 落在前方通道内"，没有任何距离概念：障碍物一进画面（往往还在 30~40cm 外）就开始绕。而整段绕行、越障、回线都是**从触发那一刻起按时间推进**的，触发点提前 30cm，回线点就跟着提前 30cm，车会在障碍物侧面还没走过去时就斜着切回原线，看起来就是"绕一半就回来"。两个现象是同一个原因，把触发点推到障碍物跟前，两个问题一起消失，不需要去改 `VA_TURN_OUT_MS` / `VA_PASS_MS` 这些时间参数。

## 距离门限：10cm 才绕行

单目一帧没法直接测距，但障碍物立在赛道上，检测框的**底边** `yb = y + h` 就是接地点：车越近，接地点在图像里越靠下。这个关系只由相机安装高度和俯角决定，与障碍物本身多大多高无关——这正是"拿框的像素大小当门槛"做不到的。

距离模型让 `1/d` 对 `yb` 线性，由两个实测点 (ROW10, 10cm)、(ROW20, 20cm) 定出：

```
1/d = 1/10 - (yb - ROW10) * 0.05 / (ROW20 - ROW10)        ROW20 < ROW10
```

代码把它放大 10000 倍做整数运算（`rows_to_inv10k` / `rows_to_cm` / `row_for_cm`），不引入浮点库。判定只看行号：`d ≤ VA_TRIGGER_CM` 等价于 `yb ≥ row_for_cm(VA_TRIGGER_CM)`。默认 ROW10=200、ROW20=104 对应 相机高10cm、俯角15°、f≈260px 的名义几何，**不是实测值**：相机装高 8cm 时 10cm 处约只有 164 行，按默认值会等到 6~7cm 才动，所以必须标一次。

标定步骤（不用让车跑）：

1. 把车摆到障碍物正前方，尺子量 摄像头镜片到障碍物前沿 = 20cm，保持不动，看 USB 串口的 `[vision]` 行，读 `yb`，填进 `VA_ROW_AT_20CM`。
2. 同样量 10cm，读 `yb`，填进 `VA_ROW_AT_10CM`。
3. 重新编译烧录，把车停在 10cm 处不动，确认 `d` 显示 10 左右、`tr` 等于触发行号。

两个细节：`yb` 在很近时会停在 239（框底边被画面底边截断，K210 也把 y+h 钳在 239 以内），默认几何下 239 约等于 8cm，再近也读不出来——正好当"极近"用，不影响触发；标定必须在真实安装位置上做，俯仰角动一点行号就差几十行。

`VA_PREDICT_MS` 补偿的是"看到的时候车已经比 10cm 更近了"：曝光一帧约 80ms、K210 卡尔曼再滞后 2 帧、串口 50ms，等电机响应，车速 0.4m/s 时这段时间车又走掉 6~10cm。代码按最近两帧底边行号的变化率外推 60ms 再判定，且只在确实靠近时外推，抖动不会造成提前触发。实测"车已经贴上才动"就把 `VA_TRIGGER_CM` 加到 12~14 或 `VA_PREDICT_MS` 加到 100；"还差很远就动"先查两个标定行号有没有写反。

完整流程：循迹 → 达标确认 → 向外转 → 斜向离线 → 回正 → 前进越障 → 向内转 → 斜向找线 → 反向转对正 → 循迹冷静期 → 正常循迹。

离线过程中至少连续3次成功读取到全白才承认离开原线；完成越障阶段后才允许找线。连续3次压线才进入对正，对正至少旋转指定时间且中间通道连续3次见线后交回原PID。灰度阵列只能提供压线位置，无法直接证明车身航向正确，因此对正最短时间仍需实车调试。左右镜像动作由VA_LEFT统一控制。

建议先固定摄像头、障碍、车速：先按上一节标定 `VA_ROW_AT_10CM` / `VA_ROW_AT_20CM`（这一步决定"10cm 才动"），再调向外转与侧移确保车身让开，接着调回正与越障时间确保车尾通过，最后调回线和对正。正常循迹速度仍由原BASE等参数控制，首次试车可用原指令降低BASE，但不要不经确认就SAVE覆盖原调参。

本版是定时绕行，不会建立地图或自动证实车尾已过障碍；靠VA_PASS_MS实测保证。绕行中继续检查通信心跳，不会根据同一个障碍框重启计时，也不会因框消失而提前回线。它没有新增绕行中第二障碍的自主重规划，适用于本次约定的同尺寸、近处不密集的静止障碍场景。

因为触发点已经挪到障碍物跟前（约 10cm），从触发到向内转的`VA_TURN_OUT_MS + VA_SHIFT_MS + VA_STRAIGHTEN_MS + VA_PASS_MS ≈ 2.2s` 才会把车送到障碍物侧后方，回线不再"提前"。若实车发现回线偏晚（车已开出很远才切回），减小 `VA_PASS_MS`；偏早（车尾还没过障碍就切回）就加长它。注意触发瞬间是原地转向、不前进，所以 10cm 处开始绕不会顶到障碍物。

## 调试与故障

模式5每秒额外输出 `[vision]`：st（状态）、fault（故障）、link（通信新鲜度）、found、x、yb（框底边行号）、d（按标定估算的距离，cm）、tr（当前触发行号）、confirm（最近3帧命中数，0~3）、left、rx/ok/bad（串口收发计数）。标定距离时就看 `yb` 和 `d`；`d` 已经到 10 但车还在走，说明确认帧数/时延补偿还需要调。

状态：0等待新心跳，1循迹，2向外转，3侧移，4回正，5越障前进，6向内转，7找线，8对正，9冷静循迹，10故障停车。

故障：0无，1通信超时，2灰度不可用/绕行读取失败，3保留，4找线超时，5对正超时。离线距离按定时参数实车调节，不再因灰度没有出现全白而锁死。发生其他故障后停车锁定，即使通信恢复也不突然起步。切走模式会停止视觉控制并清循迹历史。

按键中断现在仅提交切换请求，由原10ms后台任务执行，避免中断切走模式后旧任务继续写电机。按键顺序为1→2→3→4→5→1，其他控制语义保持。

## 为什么"地上有黑线"时视觉会变迟钝

黑线本身不会让 YOLO 失效，但它同时动了三件事，叠起来就是"屏幕偶尔能看到框、车却不躲"：

1. **自动曝光被黑线带偏**。大块黑色把画面平均亮度拉低，AEC/AGC 会提亮，白纸过曝、障碍物对比度被压平，量化模型的分数掉到阈值附近。`main.py` 现在在 `skip_frames` 之后冻结曝光与增益（`FREEZE_EXPOSURE`），**上电时先把车放在赛道上再通电**，让 AE 收敛在赛道亮度上。现场偏亮/偏暗时改 `sensor.set_auto_exposure(False, exposure_us=...)` 固定值。
2. **触发门槛把漏检放大**。旧版"连续3帧命中、漏1帧清零"，单帧检出率 p 时触发概率只有 p³（p=0.5 只有 12%）。现在改为 3 帧滑窗命中 2 帧，p=0.5 时约 50%，且漏检不再一票否决。
3. **帧率和提前量**。LCD 预览默认关闭（`LCD_PREVIEW = False`），恢复显示会掉 3~5fps；发送周期 50ms；YOLO 阈值 0.3；通道放宽到 60~260。

调参顺序建议：先看 `[vision]` 的 `found` 是否稳定为 1（不稳 = 曝光/构图问题，回第 1、3 条），再把车摆到 10cm 处看 `yb` 是否已经 ≥ `tr`、`confirm` 能否在 200ms 内到 2。只有远处有框、`yb` 远小于 `tr` 时车不动是**正常的**，这就是距离门限在工作。若 10cm 处 `found` 掉 0（贴太近、画面糊或框超出通道），把 `VA_TRIGGER_CM` 加到 12~14，或把 K210 的 YOLO 阈值降到 0.25。
