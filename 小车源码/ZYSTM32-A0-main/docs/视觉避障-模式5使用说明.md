# 模式5：K210 视觉避障（循迹 → 减速 → 绕障 → 回线 → 对正 → 恢复循迹）

模式 1（超声波融合）、2（避障）、3（循迹）、4（自检）全部保留。模式 5 = 灰度循迹 + K210 视觉触发绕障，上电默认进模式 5。本文档描述 2026-11 重构后的状态机，**与旧版（定时绕行）不兼容**：状态编号、故障码、`[vision]` 字段都变了。

## 使用

1. 打开 `USER/Template.uvprojx` 编译烧录。工程已含两个视觉 C 文件与头文件搜索路径。**必须用 Keil 重新编译生成 hex**；仓库里的 `OBJ/vision.hex` 是旧固件。
2. 将 `K210配套/main.py` 部署为 K210 启动脚本；`K210配套/通信原版.py` 是补充通信代码前的原文。
3. 接线沿用通信实验：K210 TX → 小车 PA3（USART2 RX），两板 GND 共地，115200/8N1。PA2 是 USART2 TX，本版仍不主动发送。USART1 PA9/PA10 为 USB 调试口。不要把 USB 调试的 TX 和 K210 TX 同时接到 PA3。
4. 上电默认模式 5：先按原灰度循迹跑；K210 没就绪或正常循迹阶段暂时断链时，继续灰度循迹、只是不触发视觉避障。已经开始绕行后断链 → 停车保护。USB 串口发 `5` 回车可重进模式 5，发 `3` 回车回纯循迹。
5. 模式 5 故障停车后不会自行恢复，排查后重发 `5`。

## 状态机

```
WAIT(0) ──收到视觉心跳──▶ LINE(1)
LINE    ──30cm 内 3 帧命中 2 帧──▶ SLOW(2)         收油到 60%，仍跑循迹 PID
SLOW    ──18cm 内连续 2 帧──▶ TURN_OUT(3)          提交绕行，锁定绕行侧
TURN_OUT──300ms──▶ SHIFT(4)                        原地向外转
SHIFT   ──≥550ms 且连续 3 拍看不到线──▶ STRAIGHTEN(5)   弧线侧移离线
STRAIGHTEN──320ms──▶ PASS(6)                       回正
PASS    ──≥700ms 且目标离开视野 3 帧──▶ SEEK(7)    越障，按框心位置往外修
SEEK    ──连续 3 拍压线──▶ ALIGN(8)                反方向弧线扫回原线
ALIGN   ──重心进 ±25 死区 3 拍──▶ COOL(9)           mini-P 对正
COOL    ──700ms──▶ LINE                            交回 PID，速度 55%→100% 爬升
任意段异常/超时 ──▶ FAULT(10) 停车锁定
```

控制权规则：**只有 LINE / SLOW / COOL 调用 `SearchRun()`（循迹 PID）**，其余状态一律走 `drive()`/`turn()` 自己写 PWM，不存在两套逻辑同时改电机。所有避障输出都经 `slew_step()`，每 10ms 最多变化 `VA_SLEW_STEP`(12)，不会有阶跃转向。

## 距离标定（决定"什么时候开始动"，不用让车跑）

障碍物立在赛道上时，检测框**底边** `yb = y + h` 就是接地点：越近越靠下，而且只取决于相机安装高度和俯角，与障碍物大小无关。

1. 车摆到障碍物正前方，量镜头到障碍物前沿 = 20cm，看 `[vision]` 的 `yb`，填 `VA_ROW_AT_20CM`。
2. 同样量 10cm，填 `VA_ROW_AT_10CM`。
3. 重新编译烧录，车停在 10cm 处，确认 `d` ≈ 10。

默认 200/104 是"相机高 10cm、俯角 15°、f≈260px"的名义几何，**不是实测值**。相机装低时按默认值会等到 6~7cm 才动，必炸。近处 `yb` 会被钳在 239（约 8cm），再近也读不出来，正好当"极近"用。

## 调参顺序（按现象定位，不要一上来改 PID）

| 现象 | 先动哪个 |
| --- | --- |
| 贴到障碍才动 | `VA_TRIGGER_CM` 加到 20~24；或标定行号写反 |
| 还离很远就减速 | 检查两个标定行号；`VA_SLOW_CM` 降到 25 |
| 侧移不够、擦到障碍 | 加 `VA_SHIFT_MIN_MS`（每 100ms 约 1.5~2cm 横移），或加 `VA_SHIFT_FAST/SLOW` 差值 |
| 绕过去回不来、一直找不到线 | 减小 `VA_SEEK_FAST-SLOW` 差值（切入角太陡）；加 `VA_SEEK_BUDGET_MS` |
| 回线后甩尾 | 减小 `VA_HANDOVER_PCT`；加 `VA_HANOVER_RAMP_MS` |
| 同一障碍反复触发 | 加 `VA_REARM_MS`；确认 `VA_PASS_MS` 够长 |
| 对正时来回摆 | 减小 `VA_ALIGN_GAIN`；加 `VA_ALIGN_DEADBAND` |

## 调试与故障

每秒一行 `[vision]`：

```
st=状态 fault=故障 link=链路新鲜 found=是否检出 x=框左 yb=框底边 d=估算距离cm
tr=绕行触发行 slow=减速触发行 side=本次绕行侧 arm=是否允许触发 cf=滑窗命中数
near=连续近距帧 off=连续离线拍 rx/ok/bad=串口计数
```

- 状态：0 等待，1 循迹，2 减速，3 转出，4 侧移，5 回正，6 越障，7 找线，8 对正，9 冷静，10 故障。
- 故障：0 无，1 绕行中视觉断链，2 灰度不可用/连续读失败，3 找线超时，4 两侧都堵/越障被判卡住，5 总时长超限。进故障即停车锁定，即使通信恢复也不起步，必须重发 `5`。

## 已知边界

- 仍是单目、单障碍、静态障碍方案：不建图，不做绕行途中第二个障碍的重规划。
- `yb` 与距离的关系依赖相机安装姿态，重装相机必须重新标定。
- 越障"车尾已过"是靠"时间下限 + 目标离开视野"共同判定的，不是严格证明；障碍特别宽或特别长时要把 `VA_PASS_MS` 加大。
- 绕行侧只按框心选一次，绕行途中不换边；两边都堵时直接停车（`VA_BLOCK_WIDTH_PX`）。
